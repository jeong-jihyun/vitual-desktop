# 가상PC 원격제어 프로그램 - 요구사항 (검토 확정본)

Android/웹 기반으로 개인 소유 Windows PC를 원격제어하는 도구. 최초 검토안(아티팩트)에서
논의된 내용을 바탕으로 확정된 요구사항을 정리한다.

## 확정된 결정 사항

| 항목 | 결정 |
| --- | --- |
| 제어 대상 OS | Windows 전용 (1단계) |
| 서비스 형태 | 개인 소유 PC용 개인 도구 (다중 테넌트 아님) |
| 서버 운영 | 1단계: 집 와이파이 내부(비용 없음) -> 마지막 단계(옵션): 오라클 클라우드 무료 티어 |
| 인증 방식 | 회원가입 없음. 서버에 설정한 단일 접속 비밀번호(OWNER_PASSWORD) + 1회성 PIN 코드(원격지원용) |
| 구현 방식 | 완전 자체 구현 (오픈소스 포크 아님) |
| Android | Kotlin 네이티브 (Phase 3) |
| 웹 클라이언트 | React + Vite |
| 수익화 | 없음 (무료 개인용) |
| 규모 | 개인 PC 3~5대 |
| 대상 지역 | 국내 한정 |

### 서버 운영 방식 변경 이력

최초안은 "자체 VPS 구축·운영"이었으나, 실비용 발생 부담에 대한 피드백에 따라
단계를 나누기로 했다:

1. **지금**: 집 와이파이 내부에서만 서버를 실행 (비용 0원). `server/`가 API와
   웹 화면(`web-client` 빌드 결과물)을 같은 포트에서 함께 서빙하므로, 핸드폰은
   같은 와이파이에서 PC의 사설 IP 주소로 바로 접속한다.
2. **마지막 단계(옵션)**: 오라클 클라우드 Always Free 인스턴스에 `server/`를 그대로
   배포해 집 밖에서도 접속 가능하게 한다. 서버 코드는 `PORT`/`JWT_SECRET`/
   `OWNER_PASSWORD`/`WEB_CLIENT_DIST`를 전부 환경변수로 받도록 되어 있어, 이
   단계로 넘어가도 코드 수정 없이 서버 실행 위치만 바뀐다. 실제 배포 가이드는
   이 옵션을 진행하기로 결정한 시점에 작성한다.

### 인증 흐름 변경 이력

최초안은 이메일/비밀번호 "회원가입"을 포함한 계정 시스템이었으나,
"회원가입은 필요 없다"는 피드백에 따라 다음과 같이 단순화했다:

- 서버 관리자가 `.env`에 `OWNER_PASSWORD`를 설정하면, 서버가 최초 기동 시 이를
  단일 소유자 자격증명으로 자동 등록한다.
- 웹/모바일 브라우저는 이메일 없이 이 비밀번호만 입력해 로그인한다.
- 원격지원처럼 소유자가 아닌 사람이 1회 접속해야 하는 경우를 위해,
  호스트 PC에서 직접 실행하는 `generate_guest_pin.py`로 6자리 1회성 코드를 발급하고,
  웹에서는 로그인 없이 이 코드만으로 해당 PC에 1회 접속할 수 있다.

## 시스템 구성

```
Android 앱 / 웹 브라우저  --(HTTPS/WSS 시그널링)-->  자체 VPS(서버)  <--(HTTPS/WSS)--  Windows 호스트 에이전트
        └------------------------- WebRTC(P2P 우선, 실패 시 TURN) -------------------------┘
```

- **server/** - Node.js/Express 시그널링·인증 서버. WebRTC offer/answer/ICE 중계만 담당하며
  화면·입력 데이터는 클라이언트-에이전트 간 WebRTC로 직접 오간다.
- **host-agent/** - Windows에서 실행되는 Python 에이전트. mss로 화면 캡처, aiortc로 WebRTC 송출,
  pynput으로 입력 주입.
- **web-client/** - React 웹 뷰어. 데스크톱/모바일 브라우저 모두 대상.
- **android/** - Phase 3 예정 (Kotlin 네이티브, 웹과 동일한 시그널링 프로토콜 재사용).

## Phase 1 (구현 완료)

- 접속 비밀번호 로그인, 등록된 PC 목록 조회
- 페어링 코드로 새 Windows PC 등록 (상시 등록 - 계정 기반)
- 1회성 PIN 코드로 게스트 접속 (원격지원용)
- WebRTC 기반 화면 스트리밍 + 마우스/키보드 원격 제어

## Phase 2 (구현 완료 - 보안 강화)

집 밖으로 서버를 노출하기 전에(오라클 클라우드 등) 미리 다져두는 보안 계층.

- **2FA(TOTP, 선택)**: `.env`의 `TOTP_SECRET`을 설정하면 로그인 시 비밀번호 +
  인증앱(Google Authenticator 등) 6자리 코드를 함께 요구한다. 설정하지 않으면
  기존처럼 비밀번호만으로 로그인해 하위 호환된다. 시크릿 생성은
  `server/scripts/generate-totp-secret.js` 1회 실행.
- **로그인 무차별 대입 방지**: 같은 IP에서 10분 내 5회 로그인 실패 시 이후 요청을
  일시 차단(429). 성공하면 카운터 초기화.
- **감사 로그**: 로그인 성공/실패, PC 등록/해제, 게스트 코드 발급/사용, 에이전트
  온라인/오프라인, 원격 접속 시작을 서버에 기록. `GET /api/audit`로 조회하며,
  웹 화면 하단 "활동 로그"에서 확인 가능.
- **기기 접근 제어(재확인)**: 새 PC 등록은 물리적으로 그 PC의 콘솔에 뜬 페어링
  코드를 알아야만 가능하고, 소유자가 언제든 등록된 PC를 목록에서 삭제할 수 있다 -
  이미 Phase 1의 페어링/삭제 흐름이 사실상 화이트리스트 역할을 하므로 별도 기능은
  추가하지 않았다.

## 다음 단계 (Phase 3~4, 검토 문서 기준)

- Android 네이티브 앱
- 파일 전송, 클립보드 동기화, 다중 모니터, 세션 녹화

## 보류 항목 (백로그)

- **원격으로 PC 전원 켜기 (Wake-on-LAN)**: 대상 PC가 완전히 꺼져 있으면 `host-agent`도
  실행되지 않아 지금 구조로는 켤 수 없다. 브라우저는 보안상 WOL 매직 패킷을 직접
  보낼 수 없어서, 집 안에 **항상 켜져 있는 별도 기기**(WOL 지원 공유기 또는
  라즈베리파이 등)가 매직 패킷을 대신 전달해줘야 한다. 하드웨어 전제조건이 있어
  우선순위 없이 보류. 필요해지면: 1) 공유기 자체 WOL 기능 확인, 2) 그래도 필요하면
  별도 상시 릴레이 기기 + 서버에 "wake 요청" API 추가를 검토한다.

전체 벤치마크 비교, 상세 아키텍처 다이어그램, 법적 고려사항 등은 최초 검토 아티팩트를 참고.
